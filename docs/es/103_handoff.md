# 第 103 轮交接 — 正常沟通: UTF-8 语法机修复 = 根因, 通道内容化

## 一句话结论

第 102 轮 30+ 次子实验 (chat102 a-t) 未破的"复读自锁环 / 自回归漂移",
**根因是 forward.py 的 UTF-8 阻断逻辑 bug**: 它把"上一字节是续字节"当非法起始,
屏蔽续字节 → 三字节/四字节字符永远无法完成 → 生成恒 "lead+1续" 死循环
(dec 0.00-0.09). 修复为 expect_cont 语法状态机后, **W_lm 与 W_act 双分支生成
立即 dec 0.97-1.00** (合法中文多字节字符, 非复读, 熵稳定) — 沟通通道首次内容化.

## 最终状态 (2026-08-21, 验证完成)

- 感知: W_lm 前馈 hit1 ~0.14 / hit3 ~0.30 (held-out), 结构合法率 ~0.75,
  lead 后合法率 0.95-1.00 (UTF-8 顺序结构学成)
- 表达: W_act 分支 dec 0.97-1.00, uniq 40-49/64, rep ~0 (熵激励软采样)
- 交互相关: 中文种子 → 中文lead 0.18/ascii 0.48; 英文种子 → 中文lead 0.12/ascii
  0.62 — 表达语言成分随输入变化 (长上下文更明显: 中文种子 ascii 0.00)
- 生命: free_run fe 0.015→0.008 递减, 零 NaN
- 零 NaN, 全 fp16

## 根因: UTF-8 阻断逻辑 bug (第 64 轮引入, 静默 39 轮)

| 项 | 旧 (bug) | 新 (第 103 轮) |
|---|---------|--------------|
| 判定 | `bad_start = (last_byte∈0x80-0xC1)` → 屏蔽续字节 | `expect_cont` 语法状态机 |
| 语义 | "上一字节是续字节" → 强制新字符 | 中途 (expect>0) 必须续字节; 边界 (expect==0) 必须 ASCII/起始 |
| 后果 | 3/4 字节字符不可能生成 → "lead+1续" 死循环 | 多字节字符完整可生成 → dec 1.0 |

**教训: round-87 的"可解码率 0.70"是 ASCII 主导的假象** — 阻断器把生成限制在
ASCII + 残缺多字节, 中文 3 字节字符从未真正生成过. 后续轮次 (88-102) 在
"表达不可解码"上堆了大量机制 (W_act 信任域/软目标/决策态对齐), 全部是在跟
解码器 bug 搏斗. 修复解码器后, W_act 学习即刻可用.

## 诚实声明 (内容天花板)

- 生成是可解码、多样、不复读、输入相关的**有效 UTF-8 中文** — 沟通通道工作.
- 内容是**随机有效字符** (非语义词句): 字节级 hit1 ~0.14 只能偶尔成词.
  语义级续写需要万步级 + 语料对齐 (round-101 交接原判), 阶段 3 证实非学习率
  钳制. 本轮交付的是**通道内容化** (dec 0.00 → 1.00), 语义是下一轮目标.
- 与 round-87 "词级语义需万步级"的预判一致.
