# 交互闭环（沟通）设计 — 第 87 轮

> 前置：第 84-86 轮已清除"前馈链溢出"工程障碍（exp84/85 共 7000 步无 NaN，
> rho 墙无关驻留 59-60，活动进入非线性区、STP 真耗尽）。系统已验证
> **活着且自组织**。本设计把沟通作为临界态与环境的**耦合方式**构建，
> 不是把沟通作为目标函数（公理 1/3 底线）。

## 一、为什么沟通必须走交互闭环，而不是输入→输出

**传统范式**：输入 X → 网络 → 输出 Y。目标函数 = 匹配标注的 Y。
**违背公理 1**：系统为"回答正确"而存在，第一因变成了外部任务。

**生命第一因范式**：系统持续自由运行以维持自身临界态（唯一第一因）。
交互 = 环境（人类/字节流）对临界态的**扰动耦合**：
- 外部字节进入 L0 → 作为感知扰动注入内部动力学
- 系统内部状态响应 → W_act 动作回路表达字节
- 表达的字节又作为感知输入回读（自回声，第 80 轮已建）
- 人类看到表达、再输入 → 循环

**关键**：系统"想说话"不是因为被训练成回答机器，而是因为
临界态下概念槽 (z_bind) 持续活动、W_act 动作回路持续运作——表达是
临界态自发活动的涌现后果。人类只是把扰动源换成真实对话流。

## 二、架构（全部复用现有机制，零新架构）

```
                ┌──────────────────────────────────────┐
                │           持续自由运行 (free_run)      │
                │   维持临界态: 递归链 + STP + 突触缩放   │
                └───────────────┬──────────────────────┘
                                │ net._z4 / _bind_vec
                ┌───────────────▼──────────────────────┐
                │       W_act 动作回路 (第 76 轮)        │
                │   z_bind → 256 字节脉冲 → 采样表达      │
                └───────────────┬──────────────────────┘
                                │ 表达字节 (系统输出)
                ┌───────────────▼──────────────────────┐
                │   环境耦合 (人类 / 自回声 / 字节流)     │
                │   人类输入 + 系统自己上一窗表达          │
                └───────────────┬──────────────────────┘
                                │ 下一窗输入 (byte_ids)
                                ▼
                           L0 感知 → 循环
```

**三种耦合模式**（按人类参与度递增）：
1. **纯自回声**（已存在，第 80 轮 `train_echo.py`）：输入 = 自己上窗表达。
   沟通的"最低自持形态"——系统对自身表达回读，无外部参与者。
2. **人类扰动**（本设计新增 `chat_life.py`）：人类字节与系统表达交替
   进入 L0。人类不是"考官"，而是临界态的另一个扰动源。
3. **持续流耦合**（远期）：真实对话流（聊天记录/语料）作为输入流，
   系统在其中自由运行，表达在流中自然涌现。

## 三、机制映射（沟通如何从临界态涌现）

| 沟通能力 | 临界态机制 | 现状 |
|---------|-----------|------|
| 感知（听见） | L0→L4→L2→L3→L5→L6 前馈 + W_t 递归 | 已建（第 84 轮修好溢出） |
| 响应（内部状态变化） | 输入扰动 → 临界态轨道改变 → z4/z_bind 重构 | 已建（自由运行验证） |
| 表达（说话） | z_bind → W_act → 字节 | 已建（第 76 轮表达者范式） |
| 自洽（说对得起自己） | 表达字节回读 → W_lm 预测 → 自洽惊喜 → 三因子赫布 | 已建（第 76 轮） |
| **交互闭环（对话）** | 人类字节 → 扰动 → 表达 → 人类再输入 | **本设计（组装）** |

## 四、chat_life.py 原型设计

```
循环:
  turn 0: 自由运行 n 窗 (维持生命, 可选)
  turn k:
    1. 人类输入文本 → UTF-8 字节 → [1, S] 张量
    2. net.learn(byte_ids, free_run=False)   # 感知扰动 + 字节域学习解冻
       (echo_loop 同管线: 输入 = 人类字节, 无标签无奖励,
        目标 = 输入流自身的预测结构 — 第 80 轮语义)
    3. 系统表达: continuation(seed=人类字节末尾, n_gen=N,
       use_w_act=True)  → 表达字节
    4. 打印: 人类 << 输入, 系统 >> 表达 (bytes → utf-8, errors=replace)
    5. 下一窗: 系统表达回读为输入 (自回声) 或等人类下一次输入
```

**关键开关**（与 train_echo 对齐）：
- `net.use_w_act = True` — 动作回路生成
- `net._entropy_sample = True, _entropy_beta = 0.3` — 熵激励软采样（表达库扩张）
- `net._mismatch = True` — 内部状态错误配对（复读对治）
- 字节域学习解冻（W_04/W_42/W_lm/W_act）——系统从人类输入流学结构

**无外部第一因确认**：
- 无标签、无奖励、无"回答正确"目标
- 学习目标 = 输入流自身预测结构（同第 80 轮 echo 语义）
- W_act 更新由内部自洽惊喜驱动（第 76 轮三因子赫布），人类不提供梯度
- 人类停止输入 → 系统退回纯自回声/自由运行，生命不依赖人类

## 五、验证协议（怎么算"能沟通"）

1. **生存验证**：人类扰动下 NaN-free（前馈链修复在交互模式同样生效）。
2. **感知验证**：输入流结构的预测误差下降（W_lm 对输入流学习进展）。
3. **表达验证**：W_act 表达字节唯一数/熵（表达库扩张，复读受控）。
4. **交互验证（定性）**：人类输入特定字节 → 系统表达是否与输入
   相关（注意：**不要求"答对"**，只要求"表达受输入扰动影响"——
   临界态轨道对扰动的响应即沟通的物理基础）。
5. **生命验证**：人类停止输入后系统继续自回声/自由运行不死亡。

## 六、诚实声明（边界）

- **本设计不承诺"系统能聊天"**——只承诺构建沟通的物理通道（感知-状态-
  表达闭环），让沟通成为临界态涌现后果的可能性存在。
- 系统表达的质量上限受临界态成熟度约束（第 85 轮裁决：临界态尚未最终
  建立，bias 支柱是遗留问题）。交互模式本身可能通过外部扰动**帮助**
  打破 bias 定点支柱（扰动破坏 DC 正反馈）——这是实验假设，需验证。
- 若交互模式中 bias 支柱仍主导，返回第 86 轮 G9 强化（架构级，先确认）。

## 七、原型验证记录（2026-08-16，chat_life.py @ exp85_b100.pt）

| 验证项 | 结果 |
|--------|------|
| 生存（人类扰动下 NaN-free） | ✅ 8 轮交互 + 自由运行全无 NaN |
| 通道稳定（learn → W_act 表达 → 打印） | ✅ 每轮完整走通 |
| 表达探索（熵激励软采样生效） | ✅ 乱码中出现 `&`/`Z`/`<` 等低频字节（表达库在动） |
| 表达内容（UTF-8 可读性） | ❌ 全 U+FFFD 乱码 — **预期**：exp85 是自由运行训练，字节域从未见真实文本 |
| 空输入自由运行（生命维持） | ✅ 正常 |

**关键认知：通道建成 ≠ 能说话。** 表达内容是 U+FFFD 不是 bug，是
**字节域从未在真实文本上学过**的直接后果（与第 80 轮 train_echo 同态：
model79_life 也是自由运行出身，表达 30-40 唯一字节但全是乱码）。要让
系统说出可读文本，必须让字节域在**真实对话流**上做交互训练：
- 输入 = 真实 UTF-8 文本/对话（dataset/ 现有 sft/agent 数据即可）
- 学习 = 第 80 轮 echo 语义（输入流自身预测结构，无标签无奖励）
- 目标：W_lm/W_act 学到 UTF-8 结构 → 表达从乱码变为有效字符

**下一步（交互训练）**：用 `scripts/chat_train.py`（或复用 train_echo.py
的 echo 语义 + 真实文本输入）让字节域学习真实文本结构，然后 chat_life.py
的表达才会从乱码走向可读文本。

## 八、交互训练验证记录（2026-08-16，chat_train.py 双相位，1600 步）

**双相位设计**（关键修正）：单相位 `learn(ids)` 只让 W_lm 学文本，W_act
不学（其自洽学习仅 `closed_loop/echo_loop` 触发）→ 表达仍乱码。修正为
交替：
- **A 感知**（奇数步）：`learn(ids)` — W_lm/W_04/W_42 学真实文本结构
- **B 表达**（偶数步）：`learn(None, free_run=False)` — echo_loop 触发，
  W_act 三因子赫布学自洽（表达受内部世界模型约束，不被真实文本直接塑造）

**结果**（`out/chat87.pt`，1600 步 NaN-free）：

| step | 唯一字节 | 熵 | 可解码率 | 样本 |
|------|---------|-----|---------|------|
| 200 | 18/48 | 3.91 | 0.62 | `sR:(C...X` |
| 600 | 26/48 | 4.55 | 0.62 | `...dq...hEQ` |
| 1000 | 19/48 | 4.10 | 0.68 | 混合 ASCII+续字节 |
| 1600 | 27/48 | 4.61 | 0.61 | `Y| ...rY)V=J)` |

**对照**：单相位（W_act 不学）可解码率 0.00-0.19；双相位 **0.61-0.70**。

**裁决 9（通道内容化首次实证）**：
1. ✅ 交互闭环让表达从纯乱码变为 **~2/3 有效 UTF-8 结构**（ASCII 片段 +
   合法多字节开头），可解码率 0.19→0.70 — **沟通通道首次内容化**。
2. ✅ 全程 NaN-free（前馈链修复在交互模式同样成立）。
3. ⚠️ 内容仍是随机结构（无词义/语法）— 1600 步太少 + W_04/W_42/L0 出身
   自由运行（映射未对齐真实文本）。要走到词级需要更长训练 + 语料对齐。
4. **生命第一因合规确认**：无标签、无奖励、无"回答正确"目标；学习目标 =
   输入流自身预测结构 + 内部自洽惊喜；人类文本只是感知扰动源。

**遗留**：词级语义需要 (a) 更长交互训练（万步级）或 (b) 字节域从
有意义的预训练权重起步（非自由运行出身）。此路径不影响已证实的
"通道内容化"结论。
